## 2. Shared population and renderer contract

### 2.1 Source projection

MMLU-Pro validation 70 is used only by the exact evaluator as the fixed 5-shot demonstration
source. Phase 4 target records come from all 12,032 test rows.

Before a target row enters the selector producer, project it to an allowlisted gold-free shape:

```text
dataset revision/fingerprint
split=test
question_id
category
src
question
ordered options
canonical identity
sanitized content SHA256
rendered prefix SHA256
rendered token-IDs SHA256
attention-mask SHA256
last effective prefix token index
renderer/task/chat-template provenance
```

Forbidden fields include `answer`, `answer_index`, target `cot_content`, correctness, generated
response, baseline/loop score, accuracy, answer flip, or unknown fields. Demonstration CoT text
used by the frozen 5-shot renderer is renderer provenance, not target `cot_content`; it must not be
copied into target selector records.

### 2.2 Canonical order and identity

The shared manifest is ordered by numeric `question_id`, then lowercase content hash. Reject:

- any missing, extra, duplicate, or reordered identity;
- a repeated `question_id` with different content;
- a content or prompt hash that differs between selector and outcome producers;
- independent re-enumeration based on callback, batch, shard, filesystem, or scheduler order.

The selector trajectory manifest, frozen panel, baseline, every loop cell, and final analyzer all
must close to the same 12,032 identities and order.

### 2.3 Chronology seal

The minimum irreversible sequence is:

```text
shared identity/renderer manifest frozen
  -> original/control no-loop prefix trajectories complete
  -> selector scores/ranks/eligibility/panel byte-frozen
  -> outcome access is allowed for P4-C/P4-D only
```

Before the selector-freeze receipt exists, producers must fail closed if an input path, schema,
or parsed field exposes target CoT, gold, generated answers, baseline correctness, or any loop
outcome. The fact that the same question identities are later evaluated is intentional and is
not itself leakage.

## 3. Prefix trajectory producer

### 3.1 Detection point

Use the exact evaluation prefix generated by the frozen `mmlu_pro` renderer. The human-readable
suffix may be `Answer: Let's think step by step.`, but the measurement location is determined by
the actual tokenized prefix and attention mask.

For each target:

1. render the exact 5-shot CoT prefix;
2. tokenize exactly as the corresponding baseline does;
3. run one native no-loop forward with `use_cache=false` and hidden states enabled;
4. generate zero target tokens;
5. locate the last valid prefix token from the attention mask;
6. read decoder boundaries `B_0..B_36` at that position.

`B_0` is the decoder embedding/input boundary. `B_j` is the output after decoder layer `j-1`
and before decoder layer `j`; `B_36` is the native final decoder boundary. Inclusive CLI window
`s:s+3` therefore uses entry `B_s` and exit `B_(s+4)`.

### 3.2 Full-vocabulary scalar computation

At each boundary, apply the actual frozen final norm and LM head. Do not apply final norm twice to
the native final boundary. Cast logits to float32, then compute stable log-probabilities:

```text
log_p_l = log_softmax(logits_l.float(), dim=-1)
p_l = exp(log_p_l)
H_l = -sum_v p_l[v] * log_p_l[v]
D_l = sum_v p_l[v] * (log_p_l[v] - log_p_36[v])
```

The producer may keep one final `log_p_36` and one current boundary vector on device. It must not
persist logits, probabilities, log-probabilities, full hidden states, or residual tensors.

Per boundary, persist only:

```text
boundary id/index
full_vocabulary_entropy
kl_to_final
normalized_entropy = H/log(vocab_size)             # diagnostic only
logit_rms                                            # diagnostic only
top1/top10/top100 probability mass                  # diagnostic only
finite/numerical validity flags
```

Required numerical checks:

- exactly 37 ordered boundaries;
- actual model `num_hidden_layers=36` and vocabulary size bound in provenance;
- all scalars finite;
- `D_36` is zero within the card tolerance;
- `0 <= H_l <= log(vocab_size)` within tolerance;
- top-k masses are in `[0,1]` and nondecreasing with k;
- no silent clamp, renormalization, missing-boundary fill, or float16 reduction.

### 3.3 Sharding and merge

P4-B may shard the 12,032 identities for scheduler throughput. The frozen shard manifest assigns
each canonical identity exactly once. Each shard writes to a new directory and closes its own
count/hash; the merge step restores canonical order and refuses partial or duplicate membership.

Smoke records are stored in a separate write-once root and are never merged into the 12,032
formal selector trajectories.

## 4. Outcome-blind controls

Controls use no gold, target CoT, generated token, or loop outcome and never contribute to the
selector score.

### 4.1 Template-only

Construct exactly one prompt per category, for 14 prompts total. Keep the exact
chat/few-shot/category template and final answer cue, but replace the target question and option
texts with fixed neutral placeholders. Aggregate using the original 12,032 population's frozen
category counts.

### 4.2 Option permutation

Choose a category-stratified deterministic 512-row subset from the shared manifest by identity
hash. For every selected row, derive a deterministic permutation of the option texts from the
canonical identity SHA256. Keep the option labels/slots and all renderer settings fixed. Do not
inspect or remap the correct answer. Compare the perturbed control only with the original
trajectories on the identical 512 rows.

### 4.3 Diagnostic outputs

Report original-versus-control similarity for boundary H/D curves, the width-four 25-row primary
ranking, and the two variable-width secondary rankings. High template similarity limits the
mechanism claim to a template-conditioned signal; it
does not alter the frozen score. Degenerate identical outputs, all-tied scores, or broken numerical
invariants are a P4-B blocker.

## 5. Selector analyzer

### 5.1 Window metrics

For width four and each sample `i`:

```text
E_i(s) = H_i(B_s) - H_i(B_(s+4))
K_i(s) = D_i(B_(s+4)) - D_i(B_s)
```

Point estimates are micro means over all 12,032 selector records. One category-stratified joint
bootstrap stream is reused for every window, metric, contrast, and variant:

```text
replicates=2000
seed=20260717
SE=sample standard deviation of replicate estimates, ddof=1
CI=percentile 95%, interpolation at q*(R-1)
```

### 5.2 Contrasts and support

```text
O_H(s) = E(s) - 0.5*(E(s-1)+E(s+1))
O_K(s) = K(s) - 0.5*(K(s-1)+K(s+1))
F_H(s) = E(s) - 0.5*(E(s-4)+E(s+4))
F_K(s) = K(s) - 0.5*(K(s-4)+K(s+4))
```

| Variant | Supported starts | Score |
|---|---|---|
| SHIFT | `1..31` | `min(z_OH,z_OK)` |
| FLANK | `4..28` | `min(z_FH,z_FK)` |
| CONSENSUS | `4..28` | `min(z_OH,z_OK,z_FH,z_FK)` |

The primary selector is CONSENSUS. Starts outside `4..28` are unscorable under the width-four
primary rule; do not zero-fill or interpolate that table. The separately pre-registered edge-aware
secondary table in Section 5.4 must never be used to backfill the primary selector.

### 5.3 Eligibility, rank, and abstention

A CONSENSUS window is point-eligible only when:

- center `E>0` and `K>0`;
- each comparison start `s-1,s+1,s-4,s+4` has `E<0` and `K<0`;
- the lower 95% CI is strictly positive for all four contrasts;
- equality at zero fails.

Rank all 25 supported windows by score descending, then start ascending. Select only from the
point-eligible set. The unique point top-1 must have bootstrap selection frequency at least 0.80.
No eligible window, a top tie within `1e-12`, or frequency below 0.80 produces `ABSTAIN`.

This stage uses full-vocabulary next-token entropy. The analyzer must not expose fields named
Choice Entropy or read A-J answer logits.

### 5.4 Variable-width secondary rankings

P4-B also freezes two outcome-blind secondary tables for widths `2..8`. They diagnose whether
the ranking persists across widths; they do not select the Phase 4 outcome panel.

```text
E_rate(s,w) = mean_i[H_i(B_s)-H_i(B_(s+w))] / w
K_rate(s,w) = mean_i[D_i(B_(s+w))-D_i(B_s)] / w

O_H = E_rate(s,w)-0.5*(E_rate(s-1,w)+E_rate(s+1,w))
O_K = K_rate(s,w)-0.5*(K_rate(s-1,w)+K_rate(s+1,w))
F_H = E_rate(s,w)-0.5*(E_rate(s-w,w)+E_rate(s+w,w))
F_K = K_rate(s,w)-0.5*(K_rate(s-w,w)+K_rate(s+w,w))
strict score = min(z_OH,z_OK,z_FH,z_FK)

R(s,w) = {r in {s-1,s+1,s-w,s+w} | 0<=r<=36-w}
A_H = E_rate(s,w)-mean_r_in_R E_rate(r,w)
A_K = K_rate(s,w)-mean_r_in_R K_rate(r,w)
edge score = min(z_AH,z_AK)
```

| Width | Full starts/count | Strict starts/count |
|---:|---|---|
| 2 | `0..34` / 35 | `2..32` / 31 |
| 3 | `0..33` / 34 | `3..30` / 28 |
| 4 | `0..32` / 33 | `4..28` / 25 |
| 5 | `0..31` / 32 | `5..26` / 22 |
| 6 | `0..30` / 31 | `6..24` / 19 |
| 7 | `0..29` / 30 | `7..22` / 16 |
| 8 | `0..28` / 29 | `8..20` / 13 |
| **Total** | **224** | **154** |

Standardize and rank strict 154 and edge-aware 224 separately. The cross-width tie-break is
`score descending, width ascending, start ascending`; also emit per-width ranks. The strict
width-four subset must reproduce the primary 25 scores, ranks, and eligibility. Any discrepancy
is a P4-A/P4-B blocker.

Even a strong variable-width candidate is follow-up evidence only. It must not enter `selected`,
`blind_high3`, `blind_low3`, or P4-C. Any variable-width outcome requires a new card, Gate, and
explicit user authorization after P4-D.

## 6. Known outcomes and prospective panel freeze

Before selector scoring, P4-A/P4-B freeze a `known_outcome_registry` using only artifact identity
and provenance, not favorable values. All previously seen 4B MMLU-Pro window outcomes are
excluded from the blind ranking groups.

After score computation and before any Phase 4 outcome access, freeze:

```text
selected_window = unique eligible width-4 CONSENSUS top-1, otherwise ABSTAIN
blind_high3 = three highest width-4 scores outside known_outcome_registry
blind_low3 = three lowest width-4 scores outside known_outcome_registry
fixed comparator = 15:18
baseline = no-loop
```

Blind high/low sets are disjoint. Ties use start ascending. `15:18` does not consume a blind-group
slot even when its score is extreme. The freeze artifact binds the card, implementation,
trajectories, bootstrap evidence, complete 25-row ranking, eligibility, selected/ABSTAIN,
known-outcome exclusions, panel, and all input hashes.

## 8. Frozen outcome analyzer

For every loop window on the shared 12,032 rows:

```text
gain(w) = accuracy(w) - accuracy(baseline)
G_enrich = mean_w gain(w), w in blind_high3
           - mean_w gain(w), w in blind_low3
```

Use one joint category-stratified paired bootstrap for all cells and contrasts:

```text
replicates=2000
seed=20260718
ENRICHMENT_SUPPORTED: lower95CI(G_enrich)>0
ENRICHMENT_REFUTED: upper95CI(G_enrich)<0
otherwise: ENRICHMENT_INCONCLUSIVE
```

Secondary outputs:

- per-window accuracy, gain, paired CI, flips, and exact McNemar versus baseline;
- six blind windows' selector-score/gain Spearman rho and exact 720-permutation two-sided p;
- selected versus baseline and `15:18` when selected is not ABSTAIN;
- `panel_regret=max(gain(15:18), gain(blind six))-gain(selected)`;
- selected-to-`15:18` competitive check at the card-frozen 0.30 pp margin.

If selected is `15:18`, label it a known-comparator hit and do not present it as a blind selected
window. If the selector abstains, still report the pre-frozen high3/low3 enrichment and use the
ABSTAIN label.

Every report must say that selector and outcome share the same 12,032 questions. The result tests
outcome-blind ranking within this population, not generalization to unseen prompts.

## 11. Gate execution and acceptance split

### P4-A executor verification

Implement the smallest sidecar, run Phase 4 targeted tests/help/diff check, and return the frozen
card/receipt. Do not run model/data code or a full suite unless the handoff names a material broad
regression risk.

and shared-12,032 completion closure.
